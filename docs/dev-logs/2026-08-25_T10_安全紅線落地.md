## 計畫段(動工前寫妥,第二條2)

### 目標

把 A.3〈本專案自我加嚴〉那四條從**紅線文字**變成**會擋人的程式 + 會紅的測試**:

| 紅線 | 落點 |
|---|---|
| `body` 純文字儲存與輸出,**輸出必跳脫** | 四個模板一律 `{{ }}`(不用 `\|safe`);測試送 `<script>` 進去看輸出 |
| `action_url` 只接受**同站**值,否則 **400 拒收** | `app/validation.py::validate_action_url` + **唯一寫入路徑** |
| 訊息主旨與內容**不進 log** | 全流程抓 stdout 斷言;順便釘住「單行 JSON」(共通紅線) |
| **嚴格 CSP + nonce**(契約 §4.10) | middleware 逐請求發 nonce;四個 HTML 頁的 `<style>` 都要帶 |

### 🔴 四件「壞掉不會有錯誤訊息」的事,決定了這次的做法

**① `action_url` 現在沒有任何寫入端點,而 T14 才會有。**
把驗證寫在端點上,等於在一個**還不存在的地方**設關卡;T14 動工時那是
「附帶工作」,而附帶工作最容易被忘記。
→ 因此關卡設在**寫入路徑**:新增 `repo.create_message()`,它是 `app/` 底下
**唯一**可以構造 `Message` 的地方,並以**源碼層 AST 檢查**釘住這件事
(比照 `display_name` 那條)。T14 只能穿過它。

**② 白名單用「前綴比對」會有一個經典的洞。**
`https://catsapp.sporton.com.tw.evil.tld/` 通過 `startswith(站台)` 而它是別人的網域。
→ 前綴之後**下一個字元必須是 `/` 或字串結束**。同一道也順便擋掉
`https://catsapp.sporton.com.tw@evil.tld/`(userinfo 冒充)。

**③ 只擋 `//` 不夠:`/\` 也是協定相對。**
瀏覽器會把 `/\evil.tld` 正規化成 `//evil.tld`。
→ 相對路徑的第二個字元是 `/` **或 `\`** 一律拒收。

**④ CSP 的 nonce 與模板不對上時,症狀是「整頁沒有樣式而伺服器零錯誤」。**
這與 portal 2026-08-03 踩的那次(檔案不在 mount 目錄下)**症狀完全相同**。
→ 測試必須**從回應標頭取出 nonce**,再斷言頁面裡每一個 `<style` / `<script`
都帶著**那一個**值;並斷言**兩次請求的 nonce 不同**(寫死一個等於沒有)。
→ 且 CSP 由 **middleware** 統一加,不逐路由加 —— 逐路由加的話,
下一個新頁面會忘記,而忘記不會有任何症狀。測試以**列舉所有回 HTML 的路由**
的方式驗,新頁面自動被涵蓋。

### 影響範圍

| 對象 | 影響 |
|---|---|
| 資料庫 | 🟢 **不動**。無 migration、無欄位變更 |
| 既有 API 行為 | 🟡 `_serialize` 會**丟掉**不合白名單的 `action_url`(現有資料沒有這種值) |
| 既有 UI | 🟡 四個模板的 `<style>` 加 `nonce`;所有回應多幾個安全標頭 |
| portal / VM / gateway | 🟢 不動 |

⚠ **一項可能的相容性風險**:CSP 若寫得太嚴,入口 landing 用 `<iframe>` 嵌本服務
會被 `frame-ancestors 'none'` 擋掉。現行設計是**連結而非嵌入**(T12 只加鈴鐺),
故採 `'none'`;若 T12 改為嵌入,必須改成 `frame-ancestors` 允許入口來源
—— **這件事寫進遺留問題,不靠記得**。

### 驗收標準

1. **跳脫**:`<script>alert(1)</script>` 進 `subject` / `body` / 公告 `title`,
   四個頁面輸出一律是**跳脫後的字面文字**;`<script` 不得以標籤形式出現。
2. **`action_url` 白名單**,反例**至少七則**全部 400:外部網址、`javascript:`
   (含大小寫變形)、協定相對 `//`、`/\`、前綴冒充 `...com.tw.evil.tld`、
   userinfo 冒充 `...com.tw@evil.tld`、`data:`、超長。
   正例:`/` 開頭相對路徑、`https://catsapp.sporton.com.tw/...`。
3. **輸出側也擋**:直接塞一列 `action_url = javascript:...` 進資料庫(模擬舊資料),
   頁面與 API **都不得**把它輸出成可點的連結。
4. **log**:走完登入→列表→標已讀→發公告→開頁,stdout 不得出現任何主旨/內容;
   且每一行都是**可解析的單行 JSON**。
5. **CSP**:每一個回 `text/html` 的路由都有 CSP;不得含 `unsafe-inline`/`unsafe-eval`/`*`;
   頁內每個 `<style`/`<script` 都帶**該次回應標頭裡的**那個 nonce;兩次請求 nonce 不同。
6. `bash tests/run_all.sh`(**起本機 PG**)全綠 + 突變檢查逐項確認。

### 回滾方式

純程式新增 + 模板加屬性 + 一支 middleware。`git revert` 即可;
無 migration、無資料變更。⚠ 回滾後 CSP 消失,頁面仍可用(不是相反)。

### 為什麼這樣做(關鍵決策)

**① `action_url` 的關卡設在寫入路徑,不設在端點上。**
它的唯一寫入端點(推送 API)是 **T14** 才有的 —— 設在端點上等於在一個
**還不存在的地方**設關卡,而 T14 動工時驗證是那次的「附帶工作」。
`repo.create_message()` 成為唯一入口,並以**源碼層 AST 檢查**釘住
「`app/` 底下沒有第二處構造 `Message`」。行為測試只能證明「這條路徑現在有驗」;
源碼檢查證明「沒有第二條路徑」。

**② 白名單同時在寫入側與輸出側驗。**
寫入側是 T10 才加的 —— **在它之前寫進去的列、日後手動改過的列、
被入侵寫進去的列都繞過了它**。輸出側是唯一能保護既有資料的地方。
⚠ 而輸出側「丟掉」時一定要留一行 log:靜默丟掉會讓「那顆按鈕不見了」查不出原因。

**③ `SITE_ORIGIN` 寫死,不從設定讀。**
平台在 D2″ 之下只有一個 hostname(MIS 只核可一個),所以沒有東西需要設定;
而設定檔**可以被改寬,且改寬不會有任何症狀**——釣魚連結長得跟正常連結一樣。
與 `app/authz.py` 的 `ROLE_CAPABILITIES` 同一個理由。

**④ CSP 用 middleware,不逐路由加。**
逐路由加的話下一個新頁面會忘記,而忘記不會有任何症狀。守門
`test_every_html_response_has_csp` **列舉所有回 HTML 的路由**,新頁面自動被涵蓋。
⚠ 刻意**不寫 `script-src`** —— 它落回 `default-src 'none'`,即本服務不執行任何
JavaScript(全站伺服器端算繪,現在一支腳本都沒有)。日後要加腳本必須同時
改這裡並在該 `<script>` 上帶 nonce,否則腳本被**靜默**擋掉。

⚠ 那 7 個通過的**必須誠實分類**:

  不是 T10 做出來的。
- **2 支**(`test_message_is_only_constructed_in_repo_create_message`、
  `test_good_action_url_still_renders`)是**空過**:前者因為當時 `app/` 裡
  根本沒有人構造 `Message`,後者因為當時沒有任何過濾。實作後才有意義。
- **2 支 log 測試**本來就綠(`log_event` 一直只傳 id/sub)—— 同樣是釘住現況。

**綠:** `bash tests/run_all.sh`(**已起本機 PostgreSQL**)→
文件層 **45 過 / 0 敗**、pytest **147 passed / 0 skipped**,合計 **192 項全綠**。

**突變檢查:19 項全被抓到**(修好量測工具之後的數字,見下)。

### 🔴 兩項發現

**① 嚴格 CSP 會把 `style="…"` 屬性也擋掉 —— 而 nonce 對「屬性」無效。**
nonce 只作用在**元素**上;`style-src 'nonce-…'`(不含 `'unsafe-inline'`)
會把 `<div style="…">` 整批擋掉。本專案原本有 **5 個**行內樣式屬性
(`max-width: 52rem`、三處 `font-size: .75rem`、`margin-top:1.5rem`)。
**症狀是版面走鐘而伺服器零錯誤** —— 與 portal 2026-08-03 那次
(檔案不在 mount 目錄下 → 整頁沒樣式)是同一種。
🔴 也就是說「`<style>` 帶了 nonce」**不等於**「樣式會生效」。
已全部改成 class,並新增 `test_rendered_pages_have_no_inline_style_attributes`
守住(驗**算繪後**的頁面,而不是模板原始碼 —— 註解裡會提到這個屬性名)。

**② 突變檢查的量測工具第三次出問題,而這次它會產生「假 ✅」。**
腳本把 `pytest` 的**非零離開碼**一律讀成「測試紅了 = 抓到」。
而 `-k` 選擇器打錯時:全部被 deselect 是 **rc=5**、指定不存在的測試是 **rc=4**
—— **兩者都非零**。也就是說**選擇器打錯會讓每一個突變都看起來被抓到**。
本次第一輪就有兩個選擇器打錯(`-k protocol_relative`、`-k csp` 都選不到任何測試)。

🔴 **這比前兩次嚴重**:T06 的「sed 沒配到」與 T09 的「sed 改錯語意」都會
讓結果偏向**假 ❌**(保守、會被人追查);這一次偏向**假 ✅**(樂觀、沒人會追查)。

已修:腳本現在**分辨 rc=0 / rc=4,5 / 其他**三種,rc 為 4 或 5 時明講
「選擇器選不到任何測試」。修好後重跑,**19 項全被抓到**——這個數字是修好之後測的。

⚠ 三次的共同形狀:**量測工具本身沒有測試**。
它擋不住第四種沒想到的失敗模式,所以每一輪的數字都要看它印的**警示行**,
不是只看最後那個總數。

### 對現有資料的實際影響

🟢 **無。** 無 migration、無欄位變更、無 UPDATE、無刪除。
⚠ 一項**行為**變更:既有資料裡若有不合白名單的 `action_url`,現在**不會輸出**
(那顆按鈕不見,並在 log 留 `action_url_rejected_on_output`)。本專案尚未上線,
現有資料為零,故實際影響為零。

### 遺留問題與後續建議

1. 🔴 **`frame-ancestors 'none'` 表示本服務不可被 iframe 嵌入。**
   現行設計是入口頁「連結」到本服務(T12 只加鈴鐺)。⚠ 若 T12 改成嵌入,
   這一行必須改成允許入口來源 —— 否則 iframe 是一片空白**而零錯誤訊息**。
   已寫進 T12 的驗收。
2. ⚠ **T09b 的發布表單會需要 CSRF。** 目前沒有任何 POST 表單(公告發布只有 API,
   而 API 走 JSON + 同源 cookie)。表單一出現就要一起處理,不能事後補。
3. 💡 模板的 `undefined` 目前是 Jinja2 預設(缺變數算繪成空字串)。
   改成 `StrictUndefined` 可以讓「nonce 變數打錯」變成 500 而不是靜默的
   `nonce=""`。本次不做:它會動到全部模板,而動守門要有自己的紅測試。
4. ⚠ **`Announcement` 沒有比照 `Message` 做「唯一寫入路徑」的 AST 檢查。**
   它沒有 `action_url`,所以風險較低;但 `title`/`body` 的長度驗證同樣可以被繞過。
   列為建議,不在本任務範圍。
