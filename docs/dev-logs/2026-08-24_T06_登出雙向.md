## 計畫段(動工前寫妥,第二條2)

### 目標

把登出的**兩個方向**都接起來(契約 §10):

1. **自發登出**(使用者在 inbox 按登出):先清自己的 session,再導 IdP 的 `end_session`。
   順序不能反——先導 IdP 的話,萬一使用者中途關掉分頁,本地 session 還活著。
2. **被通知登出**(使用者在別處登出,IdP 通知我方):
   `GET /inbox/oidc/frontchannel-logout` —— 免認證、冪等、只刪 cookie、回 **204**。

🔴 **為什麼這一步的失敗模式特別難查:** 契約 §10.3a 與 §10.7 各記了一種
**「端點零呼叫」**,而它們**觀測結果完全相同**:

| 原因 | 觀測 | 契約出處 |
|---|---|---|
| 登記值與 route 差一個字元 | 端點零呼叫 | §10.3a(PLM 有斜線、其他三家沒有;portal 為一個字元問了三次) |
| portal 沒把設定套用到 live realm | 端點零呼叫 | §10.7(2026-07-31 sporton_core 那次) |
| 測試時沒走 OIDC 交換(舊 cookie 直接放行) | 端點零呼叫 | §10.7 |

三者都只是「什麼都沒發生」,**沒有人會來反映**。sporton_core 與 portal 為此
各花了數小時,而且**兩邊都往「設定沒套用」查**。所以本任務的測試不去測
「端點有沒有被呼叫」(測不到),而是測**我方那一端的字串與行為**。

### 範圍與兩處要回寫的來源文件(第二條5)

執行前就已發現計畫與現實不符**兩處**,先寫在這裡,動工時一併回寫來源:

**① `docs/TDD測試計畫表.md` 的 T06 規格要改。**
它寫「帶斜線的變體必須 **404**(證明沒有靜默 redirect)」。實測 FastAPI 對
`/inbox/oidc/frontchannel-logout/` 回 **307** 導到無斜線的 route,**且保留
`sid` 與 `iss` 查詢字串**(已實測)。而 iframe 會跟隨 307。

🔴 **重新判斷後認為原規格的理由是錯的**:它把那個 redirect 當成「會遮蔽登記
不一致」的危害,但在正式環境它其實是**安全網**——萬一 portal 登記成有斜線
的變體,307 讓它**照樣生效**,而不是變成「端點零呼叫」。把它改成 404 在正式
環境買不到任何東西,只讓一個登記錯字變成致命。

**改法:** 保留 307,把斷言改成**不依賴 redirect 行為**的形式——
直接列舉 `app.routes` 斷言路徑字串**逐字**是 `/inbox/oidc/frontchannel-logout`
且**不存在**帶斜線的註冊。這才真的擋住「我方 route 漂移」,而且在 CI 裡無條件成立。

**② `docs/契約對齊盤點_v3.3.md` §4 Q1 的答案要改。**
它答 portal「登出後導向 `/inbox/`」,理由是「沒有獨立的已登出頁,`/inbox/`
未登入時就是導向 IdP 登入頁」。這個答案有兩個問題:

- `/inbox/` **現在不存在**(T08 才做),照它做登出會落在 404;
- 更根本:登出後立刻被導去登入頁,使用者**看不出登出成功沒有**,
  而萬一 SSO session 還在,他會被**靜默登回去**——那正是契約 §10 緣起
  描述的那種「登出看起來沒用」的體感。

**改法:** 改用 `/inbox/logged-out/`。它**已經在 client 的登記值裡**
(`post.logout.redirect.uris` 登記了 `/inbox/` 與 `/inbox/logged-out/` 兩個),
所以**不需要 portal 改任何設定**。
🔴 **趁函還沒發出去改**:那封覆函還沒送(T03b 遺留 #1),現在改是零成本;
發出去之後再改就是一次往返。

### 與計畫段的偏離(第二條5)

**計畫段提的改法行不通,換了另一種。** 計畫段 ①「改法」寫的是
「直接**列舉 `app.routes`** 斷言路徑字串逐字相符」。實作時發現:
本版 FastAPI(0.141)把 `include_router` 的結果包成一個 `_IncludedRouter` 物件,
列舉頂層**只拿到自動產生的 `/docs` 與 `/openapi.json`,一個實際端點都拿不到**
(連 `/inbox/health` 都不在裡面)。

改用**行為斷言**:打 client 登記值(無斜線)必須 **204**——307 就代表我方 route
多了斜線、404 代表路徑不存在,兩種漂移都抓得到,而且**不依賴任何內部結構**。
🔴 這其實比原計畫更好:靠內部結構寫的斷言會在函式庫升版時**悄悄改變它在檢查什麼**,
而它不會失敗、只會變成什麼都沒檢查。

**測試支數 8 → 9**:多的那支是 `test_frontchannel_logout_response_is_not_cacheable`
(`Cache-Control: no-store`)。它原本只列在驗收第 3 項的文字裡,沒有對應的測試名——
寫成測試才算釘住。

🔴 **計畫段保持原文不改**,它是「當時打算怎麼做」的紀錄。

### 為什麼這樣做(關鍵決策)

**① 自發登出「先清本地、再組導向」。** 本地清除是我方**能保證**的部分;
IdP 那一段是 best-effort(契約 §10.5 明講 front-channel 不是保證)。
順序反過來的話,使用者中途關分頁或 IdP 當下不可用,本地 session 就還活著。

**② front-channel 端點有**兩條**刪除路徑,不是一條。**
依 `sid` 刪 + 依本次請求的 cookie 刪。少了前者,IdP 的 iframe 在沒帶到 cookie 時
會**靜默不生效**;少了後者,**無 `sid` 的呼叫**就完全沒作用。

**③ 已登出頁用 Jinja2 模板而不是 Python 裡的字串。** `app/templates/` 這個目錄
T08 的收件匣 UI 會用到,現在建起來不算多做。⚠ T10 會加嚴格 CSP + nonce,
屆時 `<style>` 要補 `nonce`——已寫在模板的註解裡。

**④ 測試共用件搬進 `conftest.py`。** 原本 `test_logout.py` 去
`from tests.test_auth import ...` 也能跑,但那是**測試檔互相 import**:誰先被收集
會影響誰,而那種失敗是隨機的。搬完 T04 的 36 支仍全綠(純重構,第三條4)。

### 測試結果(紅 → 綠的證據)

**紅:** `python3 -m pytest tests/ -q` → `9 failed, 36 passed`
(T06 全紅、T04 全綠,證明重構沒有破壞既有測試)。

**綠:** `bash tests/run_all.sh` → 文件層 **40 過 / 0 敗**、pytest **45 passed**,
合計 **85 項全綠**(T04 結案時 76 項,+9)。

**突變檢查 6 項,全部被抓到**(明細見 `docs/TDD測試計畫表.md` §5.3)。

🔴 **其中一項第一次跑是「未被抓到」,而那是測試真的有洞:**
把「先清本地」改成 `pass`(只刪瀏覽器 cookie、不刪伺服器端 session),
測試**照樣綠**——因為原斷言只看「登出後 `/inbox/me` 回 401」,而
**刪掉瀏覽器的 cookie 也會讓 /me 變 401**。伺服器端那個 session 其實還活著,
**抄到 cookie 值的人仍然是登入狀態**。已補兩條斷言:伺服器端 session 數必須減一、
且**重放抄走的 cookie 必須 401**。補完後該突變轉紅。

⚠ 另一項「拿掉 `no-store`」第一次也顯示未被抓到,但那是**我的突變腳本寫錯**
(`sed` 的 `s///` 不跨行),不是測試的問題;用正確的方式改壞之後該測試轉紅。
**兩者的分辨很重要:一個是測試不夠力,一個是檢查工具不夠力。**

### 遺留問題與後續建議

1. ⏳ **真人冒煙留 T11**:契約 §7 的 SLO 那項明訂**測前必須清 cookie 或用無痕視窗**
   (§10.7 的理由:舊 cookie 直接放行時那次 SSO session 底下沒有我方的 client session,
   **IdP 沒有東西要通知**,而症狀與「設定沒套用」完全相同)。現無 gateway 路由可走。
2. 🔴 **知會 portal 時必須把結尾斜線一起寫出來**(§10.3a 明文要求 App 側這麼做,
   「不要讓 portal 用範例去推」)。我方值:**`/inbox/oidc/frontchannel-logout`,無結尾斜線**;
   post-logout 用 **`/inbox/logged-out/`,有結尾斜線**。兩個都要在覆函裡逐字寫。
3. ⚠ **session 在記憶體的限制對 T06 有一個具體後果**:容器重啟後 front-channel 通知
   會找不到任何 session 可刪(回 204,語意仍正確)。這不是缺陷——重啟本身已經
   讓所有人登出了。但**開副本之後就是缺陷**:通知只會到其中一個副本。
   搬到共用儲存的前置是 T07(有 DB)。
4. **`/inbox/logged-out/` 的 CSP**:T10 加嚴格 CSP 時這一頁的 `<style>` 需要 nonce,
   已寫在模板註解。漏掉的症狀是整頁沒有樣式,不是錯誤訊息。
