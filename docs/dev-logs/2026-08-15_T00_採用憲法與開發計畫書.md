### 為什麼這樣做(決策理由與捨棄方案)

1. **選址變更(DI-1)**:portal《站內信通知中心設計規劃》v1.3 §2 原選「掛 compliance」;Benny 2026-08-15 指示獨立 repo。理由與退路記錄於計畫書 §1.2,回寫 portal 文件列為 T02——不讓 portal repo 留過期選址。
2. **公告先行的里程碑排序**:系統通知依賴 S2S 契約章節(portal 尚未定稿)、人對人依賴 §4.2a 裁決——把零依賴的公告排最先上線,三個不在我方手上的閘門(DI-2/DI-3/S2S)都不阻塞 MVP。捨棄「照設計規劃階段一=公告+系統通知一起上」:那會讓上線日期押在別人的契約定稿上。
3. **契約缺口誠實列出**(計畫書 §2.3):§4.2a L1 明文「僅供管理後台顯示」——收件匣顯示寄件人名**現行契約不允許**,不寫出來就會在 M6 動工時才爆。階段一 UI 因此設計成零人名。
4. **render_docs.py 自寫而非用套件**:文件同步是紅線,工具不能因缺 pip 套件而失效;確定性輸出讓 `--check` 可以用 diff 驗漂移。捨棄人工維護 HTML(必漂移)與引入 markdown 套件(環境依賴)。
