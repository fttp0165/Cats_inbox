## 計畫段(動工前寫妥,第二條2)

### 目標

依開發計畫書 §3.1–§3.2 的架構,交付「可跑的空服務」——只有健康檢查、沒有業務功能,但**容器形態、網路隔離、base path、版本常數**全部到位,讓 M2 起的每個任務都長在合規的地基上。

具體四件事:

1. `cats-inbox-api`:FastAPI 應用,全部路由掛 `/inbox/` 前綴;`GET /inbox/health` **不查 DB**(平台容器紅線)。
2. 容器:Dockerfile non-root、`EXPOSE 8080`、二段建置(禁 `build: .` 一邊跑一邊編譯);FROM 不用 `latest`。
3. compose:`cats-inbox-api` 上 `cats-edge`(`external: true` + `name: cats-edge`,對齊指南 §2 治本寫法);`cats-inbox-pg`(PostgreSQL **15**)**不上 `cats-edge`、不對主機發布 port**;兩者皆配健康檢查與 restart policy。
4. `.env.example`:列出程式讀取的**每一個**環境變數名(不含值);缺漏即 CI 失敗。

### 影響範圍

🟢 **無影響**。本 repo 內新增檔案,不動 cats-portal、不動 VM、不動任何既有系統;無資料庫、無正式資料。gateway 路由要到 T11 才申請,本任務產出的容器尚未掛上入口。

### 驗收標準

1. `GET /inbox/health` 回 200 且 **DB 位址指向不存在的主機時仍回 200**(證明沒查 DB,不是「剛好連得上」)。
2. 健康檢查回應含版本號,且**與 `app/__init__.py` 的 `__version__` 常數同一個值**(第八條4:tag 與常數不一致等於說謊,先把單一來源釘住)。
3. 未掛前綴的路徑(如 `/health`)回 404——base path 沒設對會在上線當天才發現(契約 §4.10)。
4. compose 結構斷言全過:api 無 `ports`、pg 無 `ports`、pg 不在 `cats-edge`、`cats-edge` 為 external 且 `name: cats-edge`、無 `build:`、image 非 `latest`、兩容器皆有 healthcheck + restart。
5. Dockerfile:有 `USER` 且非 root、`EXPOSE 8080`、FROM 非 `latest`。
6. `.env.example` 涵蓋 `app/config.py` 讀取的全部變數名,且**不含任何實際 secret 值**。
7. `bash tests/run_all.sh` 全綠(含既有 21 項文件測試),CI 綠燈。

### 回滾方式

全部為新增檔案(`app/`、`tests/test_skeleton.py`、`tests/test_app.py`、`Dockerfile`、`docker-compose.yml`、`.env.example`、`requirements*.txt`)+ `tests/run_all.sh` 擴充。`git revert` 該 commit 即回到 M0 狀態;無容器已部署、無資料需還原。

### 為什麼這樣做(決策理由與捨棄的替代方案)

1. **健康檢查用「壞掉的 DB 位址」來測**:`/health` 不查 DB 是容器紅線,但「沒查」與「剛好查得到」在正常環境下觀測結果相同。把 `INBOX_DB_URL` 指向 `.invalid` 主機仍要求 200,是唯一能分辨兩者的方法。捨棄「用 mock 斷言沒呼叫 DB」:mock 綁實作細節,改寫法就假綠。
2. **路由前綴寫在應用裡,不靠 gateway 改寫**:契約 §4.10 要求 base path 等於子路徑;放進應用可讓本機/容器/經 gateway 三種情境 URL 完全一致。捨棄 `root_path` + gateway strip:那會讓本機測全對、上線後 redirect 與靜態資源全歪,而錯誤只在登入當下才現形(§4.1 已記載同型的坑)。
3. **骨架測試用靜態斷言而非真的 `docker compose up`**:這些錯誤在檔案內容就決定了,CI runner 也起不了 PG+gateway。釘在檔案層可讓錯誤在 PR 就出現。**但這代表「容器能不能真的跑起來」尚未驗證**,見遺留問題。
4. **`.env.example` 完整性用程式掃描比對**:少一個變數不會有錯誤訊息,只會在別人照著部署時以難懂的方式壞掉。`_env()` 包裝就是為了讓變數名可被 regex 掃到。
5. **run_all.sh 找不到 pytest 視為失敗**:若靜默跳過,「沒跑」與「跑過且綠」的輸出會長得一樣,共通紅線第一條(未跑過的測試不得宣稱通過)就形同虛設。
