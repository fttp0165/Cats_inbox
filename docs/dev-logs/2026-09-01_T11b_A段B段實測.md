## 2. client secret 輪替(2026-08-28 曝光事件的結案)

### 經過

2026-08-28 我給的一條 `grep` 指令**會把 client secret 印在畫面上**,
而 Benny 把輸出貼進了對話。🔴 **禁止這件事的規則就寫在那個檔案自己的檔頭裡**
(「🔐 本檔含 client secret:不進 git、**不貼聊天/工單**」),
而**違反它的操作是我從同一份文件推導出來的**。

### 處置(五步,2026-09-01 全部完成並各自驗證)

| 步 | 動作 | 確認方式 | 結果 |
|---|---|---|---|
| ① | `kcadm create clients/<id>/client-secret` | — | `① regenerate 已送出` |
| ② | 重跑 portal `idp/bootstrap/client-cats-inbox.sh` | — | `② 交付檔已重新鏡射` |
| ③ | 雜湊比對交付檔 | 與外流值的 SHA-256 比 | `✅ 已經不是外流的那個值` |
| ④ | 只換 `.env` 的那一行 | 腳本逐行比對 | `✅ 只換了第 31 行,其餘 44 行一字未動` |
| ⑤ | `--force-recreate cats-inbox-api` | pg 未被重建、DB 仍連得上 | `Up 3 days (healthy)` / `0002 (head)` |

🔴 **驗證用雜湊而不是直接看值** —— 外流的值已經在對話紀錄裡,
再貼一次不會增加曝光,但**會多留一份**;比對 SHA-256 可以得到同樣的答案而不多留。

### 🔴 三個「成功與沒做長得一樣」的坑,全部在這一輪出現

#### 坑一:bootstrap 腳本的成功與輪替無關

`client-cats-inbox.sh` 印了一整排 ✅,而它們**全部與「Keycloak 裡的值換了沒」無關** ——
它的工作是「把 Keycloak **現在**的值鏡射到交付檔」,現在的值是新是舊它不知道也不在乎。
**第一次跑完之後,實際上輪替根本沒發生**(雜湊比對抓到的)。

#### 坑二:輪替不會更新交付檔,而填值腳本從交付檔讀

我的指令稿 v1.7 寫「先輪替再填」,理由是「**輪替之後交付檔才是新值**」——
**那句話是錯的**。在 UI 或 CLI 輪替只改了 Keycloak 裡的值;
`/opt/cats-portal/idp/.env.keycloak.cats-inbox` 不會自己變。
少了「重跑 bootstrap」這一步,填值腳本會**把已經被廢止的舊值寫回 `.env`**,
而**它不會報任何錯**(那一行形狀正確、`assert n == 1` 照樣通過),
容器起得來、健康檢查 200(刻意不查 IdP),**第一個真人登入時才 `invalid_client`**。
→ 已回寫指令稿 **v1.10**,改為四步表。

#### 坑三:已部署後跑完整的 A-2 會把資料庫鎖在門外

A-2 會**重新產生 `POSTGRES_PASSWORD`** 並同步寫進 `INBOX_DB_URL`。
而 **postgres 官方映像的 `POSTGRES_PASSWORD` 只在 `PGDATA` 是空的那一次生效** ——
資料目錄已存在時整段初始化被跳過,`cats_inbox` 這個 role 的密碼**仍然是舊的**。
結果會是 `.env` 新密碼 / 資料庫舊密碼 → `password authentication failed`
→ `create_app()` 拋例外 → **api 進重啟迴圈**。

⚠ **與 2026-08-28 首次部署踩到的那次症狀完全相同,而原因相反**
(那次是**少了**密碼,這次會是**多換了**密碼)。

🔴 **原則:外流的是哪一個就換哪一個。** `POSTGRES_PASSWORD` 與 `INBOX_SESSION_SECRET`
從未離開過那台 VM。→ 已回寫指令稿 **v1.12**,③ 分「第一次部署 / 已部署」兩種情況,
並附**只換 client secret 的窄版腳本**,該腳本**逐行比對證明只動了一行才寫檔**。

而不是加 `cd`(那仍然靠人貼到、貼一半更糟)。

✅ 這一次的症狀是**好的**:`command not found` **當場就錯**,
不像貼到 portal 的 compose 那次是**靜靜地做錯事**。

### 🔴 第 3 項的症狀特別會騙人,而它現在有守門了

新增 `tests/test_docs.sh` **[8]**(文件層 64 → **65**):
逐行掃 `docs/*.md` 與 `tests/*.sh`,餵 heredoc 的那個指令若不帶 `-i` 即紅。
**先紅後綠實測過**,紅時精準指到 `docs/T11b上線指令稿.md:538`。

而這一輪的教訓正是「**沒有輸出**」本身必須被當成失敗。

⚠ **守門抓到的第一個「缺陷」是它自己**:第一版用 awk,而它的 pattern 那一行
