## 〇、起因

T08b 把五頁統一到本地 Bootstrap 5 之後,畫面是「乾淨但素」:每頁各自一個 `<h1>` + 兩顆按鈕,
沒有共同的導覽列、沒有品牌、時間印成 `2026-10-08T09:08:49.602715+00:00`、空收件匣只有一行字。
Benny 同日看過截圖後指示「介面設計美觀一點」。

## 一、目標

1. **五頁共用一份版面**(`app/templates/layout/base.html`):同一個頂部導覽列(品牌「站內信」、
   收件匣、發布公告、角色後台、回入口、登出)、同一個頁尾(登入身分 sub)、同一組 `<head>`
   (Bootstrap link、`app.css` link、帶 nonce 的 `<style>`)。頁面模板只寫內容。
2. **導覽列依能力顯示**:`發布公告` 只給 `publish_announcement`、`角色後台` 只給 `manage_roles`
   (T09b 的原則:顯示一個點下去會 403 的連結比不顯示更糟)。
3. **時間一律顯示台北時間 `YYYY-MM-DD HH:MM`**(Jinja 過濾器 `taipei`):收件匣的訊息時間、公告起迄、
   後台的「更新於」。🔴 **只改畫面層**,JSON API 仍輸出帶 `+00:00` 的 ISO 8601(`iso_utc` 不動;
   輸入側拒收不帶時區的值,輸出側就不能吐不帶時區的值 —— 那是 API 的契約,畫面是另一回事)。
4. **視覺**:同源 `app/static/assets/app.css` 放設計 token(主色、背景、圓角、陰影)、導覽列、卡片、
   徽章、空狀態;圖示一律**內嵌 SVG**(`aria-hidden`、`fill="currentColor"`);系統字型堆疊
   (CSP `font-src 'self'`,不載網路字型);light 寫死。
5. **空狀態**:收件匣沒有訊息時顯示插圖 + 一句話,不是一行 alert。

**刻意不做:** 401/403/CSRF/404 的 JSON 裸狀態改頁面(T08b dev-log §六 第 1 項,留 T12);
「標為已讀」控制(§六 第 3 項,留 T12);JavaScript(CSP 無 `script-src`);深色模式(憲法第四條 1/2);
外部 CDN 與網路字型(契約 §4.10)。

## 三、驗收標準

1. 先寫紅測試 `tests/test_ui_design.py`,改模板前**必須紅**:
   五頁都載 `{{ base_path }}/assets/app.css` 且它回 200;登入後三頁都有同一個 `<nav class="app-nav">`
   (含收件匣、回入口 `/`、登出);admin+announcer 看得到「角色後台」「發布公告」、純 `reader` 兩個都看不到;
   收件匣與後台畫面上**不得出現 `+00:00`、不得出現含微秒的時間**,且出現 `YYYY-MM-DD HH:MM`;
   `taipei` 過濾器:`2026-10-08T09:08:49.602715+00:00` → `2026-10-08 17:08`,naive 視為 UTC,`None` → `—`;
   空收件匣有 `.empty-state` 與內嵌 `<svg`;五頁零 `<script`;頁面模板一律 `extends layout/base.html`。
2. 改完 `bash tests/run_all.sh` 全綠(`test_security.py` 的 CSP / nonce / 零行內樣式 / 表單 CSRF /
   跳脫全部維持;`test_publish_form.py` 的「reader 看不到發布公告」維持)。
3. 本機算繪 + Chromium 截圖:五頁桌機 1280 / 手機 390,**scrollWidth == viewport**,console 零錯誤。
4. 反向:把導覽列的能力判斷拿掉(reader 也看到角色後台)→ 紅;把 `taipei` 改回原樣輸出 → 紅;
   把 `app.css` 的 link 拿掉 → 紅。
