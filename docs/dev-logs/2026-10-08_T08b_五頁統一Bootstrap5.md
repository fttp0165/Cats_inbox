## 一、目標

1. 五個模板全部載入**同一份本地** `assets/vendor/bootstrap.min.css`(v5.3.8,已在 repo),路徑一律 `{{ base_path }}/assets/…`,不寫死 `/inbox/`。
2. 角色後台改 Bootstrap 表格 + `.table-responsive`,手機寬不橫向捲動;加「回收件匣」。
3. 待開通、已登出改 Bootstrap 卡片;修掉 `**不會**` 的字面星號。
4. 一貫的頁首形狀(標題 + 右側動作按鈕),light 主題寫死(憲法第四條 1/2)。

**刻意不做:** 不引入 Bootstrap 的 JS(CSP 無 `script-src`,本來就零 JS);不接外部 CDN(契約 §4.10);
不動 401/403/CSRF/404 的 JSON 行為、時間格式、已讀控制(〈六〉另列)。

## 六、遺留問題與後續建議(同次 GUI 檢視看到、**不屬於本任務**的)

1. **未登入 / 無權 / CSRF 失敗 / 404 全是 JSON 裸狀態**(`{"error":"not_authenticated"}`、`forbidden`、`csrf_failed`、`{"detail":"Not Found"}`):瀏覽器使用者會直接看到 JSON。待開通頁 `/inbox/pending` 存在,但**沒有任何路徑會導過去**(403 回 JSON,不導向)。未登入要不要導向 IdP 是 T08 留給 T12 的決定 —— 建議 T12 一併把這四種做成頁面。
2. **時間顯示是 ISO UTC 含微秒**(`2026-10-08T09:08:49.602715+00:00`):使用者看不懂,且與發布頁「台北時間(UTC+8)」不一致;建議在模板層轉 `YYYY-MM-DD HH:MM`(UTC+8)。
3. **收件匣沒有「標為已讀」控制**:已讀只有 API(T08 `POST …/read`、T09 公告已讀),畫面上零 JS 也沒有表單 —— 「未讀」徽章從畫面上永遠消不掉。建議用純表單(POST + CSRF)做,維持零 JS。
4. **五頁都沒有回統一入口(`/`)的連結**;T12 的 landing 鈴鐺是從入口進來,反向也該有一條路。
5. `/inbox/health` 不接受 HEAD(405)—— 已記於進度表 §7 第 5 項。
