## 計畫段(動工前寫妥,第二條2)

### 目標

依《帳號系統接入契約(SSO/OIDC)》**v2.7** §5,向 cats-portal 送出 client 申請,取得 `cats-inbox` 的 OIDC client 與 `.env.keycloak` 樣板,解除 T04(OIDC 登入)的前置。**同函附帶 DI-2 偏離申請**(讀自己收件匣免逐人開通)——兩件同一份文件送,省一趟往返;若分兩次送,第二次的等待時間會直接疊在 M3 之後。

送出內容須涵蓋 §5 的必填項:`client_id`、redirect URI、需要的 claims/mapper、是否需 S2S、🔴 **session 形態聲明**(v2.0 起必填,聲明錯誤視同未聲明)。

### 影響範圍

🟢 **無影響**(純文件與跨 repo 送件):
- cats-inbox:新增 `docs/SSO接入申請.md`(+HTML),不動程式。
- cats-portal:於其 `DOCS/` 新增一份來文副本,推上**已指定的開發分支**;**不開 PR、不動其既有文件**——收受與否是 portal 的決定,不是我方的。
- 不動 VM、不動 Keycloak(client 由 portal 建立)、不碰任何既有系統。

### 驗收標準

1. 申請書涵蓋 §5 五項必填,且 **session 形態明確聲明為 cookie/伺服器 session**(連帶承擔 §10.3 front-channel logout 端點義務)。
2. 型別依 §5.1 **v2.1 更正判準**判定並寫出理由(判準是「誰執行授權碼交換」,不是「有沒有後端」;選錯不會報錯,直到第一次登入才失敗)。
3. redirect URI **含 `/inbox/` 子路徑前綴、完整比對、無萬用字元**(§4.1 已載明照字面登記會漏前綴,且只在登入當下才發現)。
4. post-logout redirect URI 登記**使用者實際被導去的那一頁**(§5.3 最後一坑:登記錯不只是畫面難看,而是 IdP session 根本沒被結束)。
5. DI-2 偏離申請寫明:偏離哪一條、為何、風險、緩解、**未核可前照契約全 deny**。
6. 文件合第七條(metadata + 版本歷史);md+HTML 並存;`bash tests/run_all.sh` 全綠。
7. 任務表 T03 → 🔵(送件完成、待 portal 回覆),不得標 ✅——client 尚未核發。

### 回滾方式

純新增檔案。cats-inbox 側 `git revert`;cats-portal 側該來文為獨立新檔,刪除即還原,不影響其既有文件。**尚未送出的東西不需要回滾**——本任務不觸發 portal 任何自動化。

### 為什麼這樣做(決策理由與捨棄的替代方案)

1. **DI-2 偏離與 client 申請併成一份送**:分兩次送,第二次的等待時間會直接疊在 M3 之後。前例 rf-workorder(2026-08-11)也是 client 申請與例外提案同函,portal 接得住這種形狀。
2. **主動揭露「收件匣顯示寄件人姓名現行契約無依據」,但本次不請求裁決**:那是階段二(M6)的前置,現在請求會讓 portal 在資訊不足時給出保守答案;先揭露可避免日後看起來像偷渡。捨棄「先不提」:被對方自己發現的代價高得多。
3. **偏離申請寫出「請直接駁回也可以」**:通知系統的可用性論證若換不到核可,我方要的是明確答案而非通融——含糊的默許會在上線後變成「誰准的」。
4. **推 portal 分支但不開 PR**:收受與否是 portal 的決定;開 PR 等於替對方決定議程。且系統指示未經明示不開 PR。
5. **T03 標 🔵 不標 ✅**:client 尚未核發,標 ✅ 等於謊報進度(共通紅線:誠實)。
