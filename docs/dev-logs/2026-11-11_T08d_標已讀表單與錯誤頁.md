## 〇、起因

T08b / T08c 之後,前端只剩兩個缺口(T08b dev-log §六):
1. **未讀永遠消不掉**:標已讀只有 JSON API,畫面零 JS、也沒有表單;
2. **瀏覽器看到 JSON 裸狀態**:未登入 `{"error":"not_authenticated"}`、無權 `{"error":"forbidden"}`、
   CSRF 失敗、404 —— 2026-10-08 真人冒煙時 Benny 實際看到過三種。

## 一、目標

1. 收件匣每則**未讀**訊息 / 公告旁一顆「標為已讀」(純表單 POST + CSRF,303 回收件匣);頁首一顆「全部標為已讀」。
2. **只對瀏覽器**(`Accept` 含 `text/html`、且不是 `/api/` 路徑)把 401 / 403 / 404 / CSRF 失敗算繪成錯誤頁:
   - 401 → 「請先登入」+ 登入按鈕(**不自動導向** —— 深層頁未登入要不要導向 IdP 仍是 T12 的決定);
   - 403 → 「沒有這個功能的權限」+ 「查看我的識別碼」(待開通頁)與回收件匣;
   - CSRF 失敗 → 「頁面已過期,請重新整理後再送出」;
   - 404 → 「找不到頁面」。
   🔴 **狀態碼不變**(仍是 401/403/404),只換 body;API 與非瀏覽器呼叫方仍拿 JSON。

**刻意不做:** 不自動導向 IdP(T12);不改任何 JSON API;不加 JS。

## 二、影響範圍

| 檔 | 改什麼 |
|---|---|
| `app/routes_inbox.py` | 新增 `POST /inbox/read/message`、`/read/announcement`、`/read/all`(表單欄位 `message_id` / `announcement_id`;require_csrf + `read_own`);收件匣 context 補 `csrf_token` |
| `app/templates/inbox.html` | 未讀卡片加「標為已讀」表單;頁首「全部標為已讀」 |
| `app/templates/error.html` | **新增**,extends 共用版面 |
| `app/main.py` | 錯誤處理:瀏覽器請求算繪 `error.html`,其餘維持 JSON;補 Starlette 404 的處理 |
| `app/static/assets/app.css` | 表單按鈕樣式 |
| `tests/test_ui_finish.py` | **新增**守門 |

- 🟢 對資料:**只寫 `is_read`/`read_at` 與 `announcement_read`**,與既有 API 同一條 repo 函式(冪等)。
- ⚠ 表單 id **形狀不對 → 400**(不是 403):`tests/test_csrf.py` 的列舉守門會帶假值 `x` 打每一支表單路由,
  而「帶 token 卻 403」會被它判成 CSRF 壞了;合法 UUID 但不是自己的 → 403(與 API 同一分界)。

## 三、驗收標準

1. 紅測試先紅:標已讀表單存在且帶 CSRF;POST 後 303 且資料庫變已讀;別人的訊息 403 且不變;
   全部標已讀後未讀數 0;瀏覽器 401/403/404/CSRF 回對應狀態碼 + HTML 錯誤頁(含共用版面、無 JSON);
   **非瀏覽器仍回 JSON**(既有測試全綠即證)。
2. `bash tests/run_all.sh` 全綠;`test_csrf.py` 列舉守門自動涵蓋新路由。
3. 截圖:收件匣有未讀 + 按鈕、錯誤頁,桌機 / 手機無橫向捲動。
