### 🔴 三項最有價值的發現

1. **契約 v2.17 的驗法可以現在就用**:拿一個壞 code 打 token 端點,回 `400 invalid_grant` 就證明 secret 正確、`invalid_client` 就是錯的。**用一個必定失敗的請求證明另一件事**——不需真人登入、不需 gateway 路由。我方 secret 一到手就能先驗,不必等 T11。
2. **v2.14 的 PLM 事故有我方版本**:它因 Django `reverse()` 回後註冊者,實際送出的 `redirect_uri` 與登記值不同,**首登即 mismatch,而錯誤停在 Keycloak 頁面、app 的 log 是空的**。我方雖非 Django,但 router 前綴或 `root_path` 會造成同型結果。已列 T04 驗收:**登入前印出實際要送出的值,逐字比對**。
3. **§11.5 讓我方原本的 T14 驗收是錯的**:我方寫「缺 scope → 401」,而契約明訂 **401=憑證無效、403=憑證有效但無此權限**,混用會讓呼叫方查不出是憑證錯還是授權不足。已更正。

### 找到我方自己的一處矛盾

`docs/開發計畫書.md` §2.1 寫「首登自動建 user(**零角色**)」,而同一份文件 §2.3-3 已寫 DI-2 核可自動授 `reader`。**兩處講同一件事,一處過期,而拿 §2.1 當規格的人會做出錯的實作。** 已修。這與契約 v2.10 修 §6/§9 打架、v3.2 修檔頭/§9 打架是同一種漂移。
