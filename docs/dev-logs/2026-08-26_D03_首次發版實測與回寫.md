### 🔴 一條測試的理由到期了,不是它壞了

`tests/test_release.py:161`:

```python
assert "尚未" in text or "未實際" in text, "🔴 SOP 沒有標註哪些步驟還沒真的跑過"
```

它釘的是**一個當時為真的暫時狀態**。現在 workflow 跑過了,而 SOP 裡仍有兩件
真的還沒跑(VM 部署、gateway 路由),所以這條**照樣綠** ——
🔴 **而那正是問題**:它會在四件事全部完成、§0 整節被刪掉之後才紅,
到時人只會把 `"尚未"` 三個字補回文件裡讓它閉嘴。

→ 處置:改成釘**不會到期的性質** —— §0 那張表必須存在,且每一列都要帶
`✅` 或 `⏳` 狀態記號;把「哪一件還沒跑」交給文件本身講,
測試只保證**那張誠實表不會消失**。

### 為什麼這樣做(關鍵決策)

**① 把「哪些步驟還沒跑過」從測試搬回文件,測試只守那張表存在。**
原斷言 `"尚未" in text` 釘的是一個**當時為真的暫時狀態**。四件事全部完成的那天
它才會紅,而那天的正確反應是刪掉 §0 —— 於是人會把「尚未」三個字補回去
讓測試閉嘴,**文件反而變成假的**。改成驗「§0 存在 + 每列帶 ✅/⏳」之後,
文件可以誠實地全部變 ✅,而**表本身不能消失**。

**② 特地離開 GitHub 去問 registry。**
workflow success **不代表**推的東西是對的:「有沒有推 `latest`」與
「別人拉不拉得到」都不在 workflow 的輸出裡。
🔴 第二件對 T11 是硬需求:GHCR 新套件**預設 private**,若是 private,
VM 上 `docker compose pull` 會 `unauthorized`,而**那個步驟沒有寫在任何部署
文件裡** —— 症狀出現的時機與 T10c 想擋掉的 `manifest unknown` 完全一樣
(低峰窗口、gateway 等著 reload)。實測 **public、匿名 200**,已寫進 SOP。

**③ Release 頁的那一句不自行改。** 見遺留問題 1。
