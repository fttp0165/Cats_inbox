## ⑥ 🔴 B-1:容器在重啟迴圈裡 —— `INBOX_DB_URL` 少了 `+psycopg`(2026-08-29 00:30)

`up -d` 成功、pg **healthy**,而 api 反覆重啟:

```
Error response from daemon: Container 749eec745cbc… is restarting, wait until the container is running
Did not find any relations.            ← pg 正常但空的(migration 還沒跑)
```

### 根因

| 事實 | 值 |
|---|---|
| `requirements.txt` | `psycopg[binary]==3.2.3` —— **psycopg 3**,沒有 psycopg2 |
| SQLAlchemy 2.0 對 `postgresql://` 的預設 dialect | **psycopg2** |
| `tests/pg_local.sh:42` 給測試的 URL | ✅ `postgresql+psycopg://…` |
| `app/main.py:91` 的 fallback 預設值 | ✅ `postgresql+psycopg://…` |
| **`.env.example` 那一行** | ❌ `postgresql://…` |

🔴 **程式碼知道正確答案,而部署樣板不知道。**
`create_engine()` 在**建立時**就載入 dialect → `ModuleNotFoundError: psycopg2`
→ `create_app()` 拋例外 → restart policy 是 `unless-stopped` → **重啟迴圈**。
⚠ **症狀不是「連不上資料庫」,是容器根本沒起來** ——
而 `docker compose ps` 只說 `health: starting`,`docker inspect` 則直接拒絕回答。

### 🔴 兩件事各自是「第二次」

**① 同一行、同一類的第二次。** 2026-08-28 我為這一行加的守門
`test_env_example_db_url_carries_a_password_slot` 只檢查**密碼欄位** —— **一半**。
於是同一行以**第二種方式**錯了一次(driver)。
→ 已補 `test_env_example_db_url_driver_matches_installed_dbapi`,
並把它與 `requirements.txt` **綁在一起**驗:哪天換回 psycopg2,兩邊會一起紅,
而不是靜靜地不一致。

**② 「測試碰不到部署樣板」的第二次。** 測試一律走 `INBOX_TEST_DB_URL`
(`pg_local.sh` 給的是對的那個),而 `.env.example` 的那一行
**只在真的部署時才被讀到** —— 兩次都是同一個盲區。
⚠ 這個盲區還有多大不知道:`.env.example` 有 14 個變數,而**沒有任何測試
會用它們啟動一次應用**。💡 建議(未做):加一支測試,用 `.env.example`
的值(secret 填假值)呼叫一次 `create_app()`,只驗它不拋例外 ——
那會一次覆蓋掉這整個盲區。

### 處置

| # | 做什麼 | 狀態 |
|---|---|---|
| 1 | `.env.example` 的 driver 改 `postgresql+psycopg://` + 逐行註明症狀 | ✅ |
| 2 | 新守門(與 `requirements.txt` 綁定),**先紅後綠** | ✅ 249 項全綠 |
| 3 | VM 上一行 `sed` 改 scheme(不動密碼)+ `--force-recreate` | ⏳ 待執行 |
