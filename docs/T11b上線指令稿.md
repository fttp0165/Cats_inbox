## 🔴 每一個 `docker compose` 都帶絕對路徑的 `-f`,不靠 cwd

本稿所有 compose 指令都寫成:

```
sudo docker compose -f /opt/cats-inbox/docker-compose.yml <子命令>
```

⚠ **2026-08-28 實測踩到一次:** 前一個指令區塊的工作目錄是 `/opt/cats-portal`
(輪替 client secret),下一個是 `/opt/cats-inbox`(B 段),而指令裡**沒有 `cd`** ——
於是 `sudo docker compose up -d` 打到了 **portal 的 compose**,
`compose ps` 列出來的是 `portal-landing`(`SERVICE=landing`)。

🔴 **那一次沒有造成損害** —— `portal-landing` 顯示 `Up 2 days (healthy)`,
compose 判定現況已符合規格就沒有重建它。**但那是運氣**:
portal 的 compose 與運行中狀態只要有任何漂移,那一下就會**重建入口頁的容器**。

🔴 **這是第九條11 的第二個邊界**(第一個是「那個目錄是什麼」,見第 0 步):
**標示標的是「我應該站在哪裡」,而它不會把 shell 移過去。**
→ 處置**不是**在每個區塊前面加 `cd`(那仍然靠人貼到、且貼一半會更糟),
而是**讓 cwd 不再有影響** —— `-f` 帶絕對路徑,compose 的 project 目錄
跟著那個檔案走,`.env` 也從那裡讀。

## A 段:VM 前置(不需要低峰窗口)

### A-1 建部署目錄並放入 compose

> 🖥️ **在哪執行:** Cats VM(ssh 進去)· 工作目錄 `/opt`

```bash
sudo mkdir -p /opt/cats-inbox
sudo chown "$USER":"$USER" /opt/cats-inbox
```

⚠ **A-1 之後還不能跑 `docker compose config`** —— 目錄裡還沒有 compose 檔,
它會回 `no configuration file provided: not found`。那兩行驗證在 **A-3 之後**。
(2026-08-28 實測:這個順序真的會被搞混,因為兩者都在 A 段裡。)

🔴 **不在正式機 `git clone`**(平台紅線:部署是改 tag 後 pull,不在正式機
`git pull && build`)。但**也不要手貼 compose 的內容** ——

> 🔴 `docker-compose.yml` 裡有 `${POSTGRES_DB}` 與 `$${POSTGRES_USER}`。
> 用**未加引號**的 heredoc 貼會被 shell 展開:`${…}` 變成空字串、
> **`$$` 變成 shell 的 PID** —— 檔案看起來還像 YAML,而 pg 起不來,
> 而錯誤訊息不會提到「你貼壞了」。

**改成從 tag 抓那兩個檔**(只抓兩個檔,不是 clone repo):

> 🖥️ **在哪執行:** Cats VM(ssh 進去)· 工作目錄 `/opt/cats-inbox`

```bash
B=https://raw.githubusercontent.com/fttp0165/Cats_inbox/v0.1.1
curl -fsSL "$B/docker-compose.yml" -o docker-compose.yml
curl -fsSL "$B/.env.example"       -o .env          # 之後就地填三個值
grep -n 'cats-inbox-api:' docker-compose.yml        # 🔴 必須看到 image: …:0.1.1
```

🔴 **URL 釘的是 tag `v0.1.1`,不是分支。** 釘分支的話,compose 會跟著 `main`
往前走,而**映像停在你部署的那一版** —— 兩者不一致而**沒有任何錯誤訊息**
(這正是第八條4 在講的同一件事,只是換到部署面)。
✅ 2026-08-28 實測:兩個 URL 皆 **HTTP 200**,且 tag 上的 compose `image` 就是 `0.1.1`。

### A-2 填 `.env` 的三個必填值

> 🖥️ **在哪執行:** Cats VM(ssh 進去)· 工作目錄 `/opt/cats-inbox`
> 📄 **編輯哪個檔:** `/opt/cats-inbox/.env`(A-1 已從 `.env.example` 抓下來)

**要填的其實是四處,不是三個** —— 🔴 第 4 處是 2026-08-28 首次部署才發現的:

| # | 變數 | 從哪裡來 |
|---|---|---|
| 1 | `POSTGRES_PASSWORD` | 自行產生 |
| 2 | `INBOX_SESSION_SECRET` | 自行產生 |
| 3 | `INBOX_OIDC_CLIENT_SECRET` | 🔴 **這台 VM 上的** `/opt/cats-portal/idp/.env.keycloak.cats-inbox`(600)|
| 4 | 🔴 **`INBOX_DB_URL` 裡的密碼** | **與第 1 項一模一樣** |

🔴 **第 4 處為什麼會漏,以及漏了的症狀:**
`app/config.py` 把 `INBOX_DB_URL` **逐字**當連線字串用(不會自己補密碼),
而 postgres 官方映像在有 `POSTGRES_PASSWORD` 時以 scram-sha-256 要求驗證。
⚠ **症狀指錯方向**:健康檢查刻意不查 DB,所以容器 healthy、`/inbox/health` 回 **200**,
而 **B-3 的 `alembic upgrade head` 才失敗**於
`password authentication failed for user "cats_inbox"` —— 看起來像 migration 的問題。
✅ 已加守門 `test_env_example_db_url_carries_a_password_slot`,`.env.example` 改為佔位字串。
⚠ **從 tag `v0.1.1` 抓下來的 `.env.example` 仍是舊的那一行** —— 這一處要手改
(下面的腳本會一併處理)。

### 🔴 順序:client secret 若曾外流,**輪替 → 重跑 portal 的 bootstrap → 才填**

⚠ **本節 v1.7 寫的是「先輪替再填」兩步,那是錯的 —— 中間少了一步**(2026-08-31 更正)。
原文寫「輪替之後交付檔才是新值」,**而交付檔不會自己變新**:

| 步 | 動作 | 誰改了什麼 |
|---|---|---|
| ① | Keycloak Admin UI → Regenerate | **只有 Keycloak 裡的值變了** |
| ② | 🔴 **重跑 `idp/bootstrap/client-cats-inbox.sh`** | 它**自 Keycloak 讀當前 secret** 並改寫交付檔(600) |
| ③ | 把新值寫進 `/opt/cats-inbox/.env` —— 🔴 **分兩種情況,見下** | 它**從交付檔讀** |
| ④ | `up -d --force-recreate cats-inbox-api` | 容器重讀 `.env` |

#### 🔴 ③ 的兩種情況:**已經部署過的話,不可以跑完整的 A-2**

| 情況 | 用哪一段 |
|---|---|
| **第一次部署**(`/opt/cats-inbox` 剛建、pg volume 是空的) | 下面 A-2 的完整填值腳本 |
| **已經部署過**(容器跑著、5 張表已建) | **只換 client secret 的窄版**(見下) |

🔴 **為什麼已部署後不能跑完整 A-2 —— 它會把資料庫鎖在門外:**
A-2 會**重新產生 `POSTGRES_PASSWORD`** 並同步寫進 `INBOX_DB_URL`。
而 **postgres 官方映像的 `POSTGRES_PASSWORD` 只在 `PGDATA` 是空的那一次生效** ——
資料目錄已存在時整段初始化被跳過,**`cats_inbox` 這個 role 的密碼仍然是舊的**。
結果:`.env` 是新密碼、資料庫是舊密碼 → `password authentication failed for user "cats_inbox"`
→ `create_app()` 拋例外 → **api 容器進重啟迴圈**。
⚠ **與 2026-08-28 首次部署踩到的那次症狀完全相同**,只是原因相反
(那次是**少了**密碼,這次會是**多換了**密碼)。

🔴 **原則:外流的是哪一個就換哪一個。** 本次外流的只有 client secret,
`POSTGRES_PASSWORD` 與 `INBOX_SESSION_SECRET` 從未離開過那台 VM,沒有理由動它們。

**③ 的窄版(已部署時用這個):**

> 🖥️ **在哪執行:** Cats VM(ssh 進去)· 工作目錄**任意**(路徑全部寫死)
> 📄 **編輯哪個檔:** `/opt/cats-inbox/.env`
> 🏷️ **動到誰的東西:** cats-portal 的交付檔(**唯讀**)

```bash
sudo python3 - <<'SECONLY'
import re, pathlib
SRC = pathlib.Path("/opt/cats-portal/idp/.env.keycloak.cats-inbox")
ENV = pathlib.Path("/opt/cats-inbox/.env")
old = ENV.read_text()
m = re.search(r'^INBOX_OIDC_CLIENT_SECRET=(.+)$', SRC.read_text(), re.M)
assert m, "交付檔裡找不到 INBOX_OIDC_CLIENT_SECRET"
new, n = re.subn(r'^INBOX_OIDC_CLIENT_SECRET=.*$',
                 'INBOX_OIDC_CLIENT_SECRET=' + m.group(1).strip(), old, flags=re.M)
assert n == 1, f"替換了 {n} 處(應為 1)"

# 🔴 證明「只動了那一行」—— 逐行比對,任何其他行有差就中止。
#    少了這一段,腳本改壞別的變數也一樣印成功(本專案記過多次的形狀)。
diff = [i for i, (a, b) in enumerate(zip(old.splitlines(), new.splitlines()), 1) if a != b]
assert len(old.splitlines()) == len(new.splitlines()), "行數變了,中止"
assert len(diff) == 1, f"動到了 {len(diff)} 行(應為 1):第 {diff} 行"
ENV.write_text(new)
print(f"✅ 只換了第 {diff[0]} 行的 client secret,其餘 44 行一字未動")
SECONLY
```

🔴 **跳過 ② 的後果,以及為什麼查不出來:**
A-2 的腳本會**把那個已經外流、而且已經被 Keycloak 廢掉的舊值寫回去** ——
而它**不會報任何錯**(那一行的形狀完全正確,`assert n == 1` 照樣通過)。
容器起得來、健康檢查 200(它刻意不查 IdP),
**第一個真人登入時才 `invalid_client`**。
⚠ 這與 T10c / T10d / DB 密碼 / DB driver 是**同一個形狀**:
每份文件都對,而把它們接起來的那一步不在任何人的清單上。

**② 的指令(🔴 絕對路徑,不靠 cwd):**

> 🖥️ **在哪執行:** Cats VM(ssh 進去)· 工作目錄**任意** —— 這個指令刻意不靠 cwd
> 🏷️ **動到誰的東西:** cats-portal(它的 idp 腳本與交付檔)

```bash

```

### D-3 冒煙(這一段才是 T11b 的驗收)

```bash
curl -skI https://catsapp.sporton.com.tw/inbox/health | head -1     # 期望 200
curl -sk  https://catsapp.sporton.com.tw/inbox/health               # version 應為 0.1.1
curl -skI https://catsapp.sporton.com.tw/inbox   | head -1          # 期望 301 → /inbox/
# 🔴 既有路由 zero-diff(gateway-apply.sh 已驗過,這裡再看一次)
for p in / /plm/ /core/ /upload/ /sysadm/; do
  printf '%s ' "$p"; curl -sk -o /dev/null -w '%{http_code}\n' "https://catsapp.sporton.com.tw$p"
done
```

**不成功怎麼退回去:** `ops/gateway-apply.sh` 的五條路由驗證**不通會自動回滾**。
若它自己回滾失敗(它會大聲說),備份在它印出的路徑;手動回復後
`sudo docker exec portal-gateway nginx -s reload`。

### D-4 真人冒煙(§10.7:測前清 cookie / 用無痕)

1. 無痕開 `https://catsapp.sporton.com.tw/inbox/` → 導向 Keycloak → 登入 → 回到收件匣;
2. 登出 → 換另一個帳號登入 → 🔴 **收件匣不得仍是前一人**;
3. 有 `announcer` 的帳號開 `/inbox/announcements/new` 發一則公告,確認它出現在收件匣頁。
