## 3. 現在能用什麼(以及怎麼親眼看到)

⚠ 目前只能**在開發機**看到 —— 統一入口的 `/inbox/` 路由還沒生效(T11b)。

| 能力 | 怎麼看 |
|---|---|
| 健康檢查(不查 DB) | `curl localhost:8080/inbox/health` → `{"status":"ok","version":"0.1.0"}` |
| OIDC 登入 / 登出 / SLO 端點 | 需 `.env` 三個必填值;缺任一則**登入路由刻意不註冊**(T01 的回滾閥門) |
| 收件匣頁(訊息 + 有效公告) | `/inbox/` —— 階段一**零人名**,只顯示 `source_app` 標籤與「平台公告」 |
| 公告發布頁(`announcer`) | `/inbox/announcements/new` —— 表單 + CSRF + 五種 400 的錯誤框 |
| 角色後台(`admin`) | 指派角色、`reader` 單獨停用、顯示名稱快取清除 |
| 容器映像 | `ghcr.io/fttp0165/cats-inbox-api:0.1.0`(**匿名可拉**,digest `sha256:90d5a6f9…`) |

🔴 **還不能做的事**(誠實標示,不是缺漏):從統一入口進入(T11b)、入口未讀鈴鐺
(T12,portal 側)、各系統推送系統通知(T14)、人對人站內信(M6)。

## 6. 🔴 已知但尚未驗證的三件事

這一節刻意獨立 —— 它們**不是待辦事項**,是「我們相信但沒看過」的東西。

| # | 相信什麼 | 為什麼還沒驗 | 錯了會怎樣 |
|---|---|---|---|
| 1 | `proxy_pass http://cats-inbox-api:8080;`(**不加尾斜線**)會原樣轉發 `/inbox/…` | 開發機**沒有 nginx** | **全站 404,而 gateway 這一層完全正常**。由 T11b 第 4 步的 staging `probe` 驗 |
| 2 | migration 在 **PG 15** 上 up→down→up 通過 | 開發機只有 **PG 16.13** | 平台紅線是 PG 15。T11b 於 VM 補 |
| 3 | 容器在真的 Docker 上啟動、容器內 discovery 連得到 Keycloak | 開發環境**無 docker daemon** | `INBOX_OIDC_INTERNAL_BASE` 填錯會組出 `/realms/sporton/realms/sporton` → discovery 404,而**離線測試全綠,只在第一個真人登入時出現** |
