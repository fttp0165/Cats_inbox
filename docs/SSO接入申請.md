## 0. TL;DR(給 portal 的五句話)

1. 申請 **confidential** client `cats-inbox`(PKCE S256 疊加),redirect URI 一條、完整比對、含 `/inbox/` 前綴。
2. **session 形態聲明:cookie / 伺服器 session** → 依 §10.3 承擔 front-channel logout 端點義務,路徑已定。
3. claims 只要 `name`(用途受限,見〈參〉);**不申請** `email`、**不申請** `groups`。
4. 隨函一件:**開通政策偏離申請**——「讀自己的收件匣」請准首登自動授 `reader`,寄信與發公告維持 deny-by-default 手動開通(詳〈伍〉)。**未核可前照契約全 deny,不先斬後奏。**
5. 另預告兩件、本次都不請求:`/inbox/` 閘道路由(〈肆〉)、S2S 推送驗證規格(〈陸〉,我方為第三個 S2S 需求且角色相反)。

## 貳、session 形態聲明與 SLO 端點(§10)

**聲明:cookie / 伺服器 session。** 屬 §10.1 第一列,front-channel logout 為 **MUST**,我方承擔。

| 項目 | 我方承諾(依 §10.3 規格逐項) |
|---|---|
| 端點 | `GET https://catsapp.sporton.com.tw/inbox/oidc/frontchannel-logout` |
| 行為 | 清除本系統 session cookie,回 **204** |
| 認證 | **免認證**(iframe 載入時不帶我方 API token) |
| 冪等 | 重複呼叫、session 已不存在時同樣 204 |
| 副作用 | 🔴 **只刪 cookie**;不建 session、不寫業務資料——被任意第三方呼叫的最壞後果=使用者被登出 |
| 參數 | `iss`/`sid` **帶與不帶都能處理**(我方 session 無狀態比對需求,忽略即可) |
| 時序 | 端點隨我方 T06 實作;**上線後知會 portal** 登記 `frontchannel.logout.url` 並回讀驗證(§10.3 時序不敏感) |

cookie 屬性依 §4.10 同源義務:`Path=/inbox/` + `HttpOnly` + `SameSite=Lax` + `Secure`。

**冒煙承諾:** 上線前依 §7 逐項驗證,登出拆「我方發起 / IdP 發起」兩條;
IdP 發起項 🔴 **測試前必清本系統 cookie 或用無痕視窗**(§10.7:不清的話舊 cookie 直接放行、沒走 OIDC 交換,IdP 手上沒有我方 client session 可通知,**端點零呼叫的症狀與「設定沒套用」完全無法區分**——sporton_core 與 portal 為此各花了數小時)。此點已寫入我方 `docs/TDD測試計畫表.md` 的 T12 驗收要點。

## 參、`name` claim 的用途聲明(§4.2a L1,自我設限)

我方業務庫依 §4.2 **只存 `sub` + 本地角色**。申請 `name` 僅為**管理後台**辨識使用者(派角色時看得出來是誰),完全落在 §4.2a **L1** 條件內:

| L1 條件 | 我方落實 |
|---|---|
| 僅自本人登入的 ID token 取得;不呼叫 Admin API | ✅ 僅登入時寫入 |
| 每次登入覆寫、無背景同步 | ✅ |
| **僅供管理後台顯示**,不出現在一般使用者可見頁面、不進 API 回應 | ✅ 見下方紅字 |
| 不得作為任何授權判斷依據 | ✅ 授權只認當次 token 與本地角色 |
| 不進 log | ✅(我方另有自我加嚴:訊息主旨與內容亦不進 log) |
| 欄位 nullable,為空不阻斷功能 | ✅ 退回顯示 `sub` |
| 提供整批清除工具、涵蓋孤兒快取 | ✅ 列入 T05 驗收 |

🔴 **我方主動聲明一個限制,並據此調整了產品設計:**
站內信的收件匣若對一般使用者顯示寄件人姓名,**牴觸 L1 第 3 條**(不得出現在一般使用者可見頁面)。因此**階段一(系統通知＋公告)刻意設計為零人名**——通知顯示來源系統標籤(如「TRF 系統」)、公告顯示「平台公告」。
人對人站內信(階段二)確實需要顯示寄件人是誰,那**現行契約沒有給路**;我方將於階段一穩定後另案提出契約增修申請(暫定提案:寄件當下自**寄件人本人**的 token 取 `name` 寫入該則訊息作為快照,不同步、不查 Admin API),**在裁決之前不實作、不上線**。
本次不請求裁決此事,僅先揭露,以免日後看起來像偷渡。

## 伍、開通政策偏離申請:「讀自己的收件匣」請准首登自動授 `reader`

### 一、申請內容

| 動作 | 申請的授權方式 |
|---|---|
| 讀**自己**的收件匣、標自己的訊息已讀、看有效公告 | **首登自動授 `reader` 角色** ←(這是偏離) |
| 寄人對人站內信(`sender`) | 維持 deny-by-default、管理後台手動開通 |
| 發布公告(`announcer`) | 維持 deny-by-default、管理後台手動開通 |
| 管理(派角色、清快取)(`admin`) | 維持 deny-by-default;bootstrap 清單 + 手動開通 |

**偏離的是哪一條:** §4.3/§4.4「首登建本地 user(零角色)→ 所有業務功能 403 待開通」中,**僅「讀自己收件匣」這一項**。其餘一字不動。

### 二、為什麼提這個偏離

1. **通知中心的可用性等於「送得到」。** 逐人手動開通的結果是:系統推了通知、使用者收不到,而且**畫面上一切正常**——他只看到待開通頁。**通知系統最糟的失效模式不是報錯,是安靜地沒送到。**
2. **這個代價貴方已經記載過。** §4.2a D7-7 裁決文自陳:deny-by-default 之下「上線首日會有一批同時湧入的待開通帳號,ADMIN 處理完之前那些人看到 403——**功能正確,體感像壞了**」。對一般業務系統這是可承受的;對**全平台的通知管道**,它會讓每一個接進來的來源系統一起看起來壞掉。
3. **這裡沒有「別人的資料」可被越權讀取。** `reader` 能讀的集合恆等於 `recipient_sub == 自己`。它不是「先給權限、之後收回」,而是**這個角色的可及範圍在定義上就只有本人**。
4. 平台規模參考:PLM 正式環境 **206 位使用者**(貴方憲法 v1.7 更正值)。逐人開通通知讀取權,行政成本與其換得的安全性不相稱。

### 三、風險與緩解(誠實列出,不粉飾)

| 風險 | 緩解 |
|---|---|
| 自助註冊帳號(限 `@sporton.com.tw`)一登入就有收件匣 | 他只會看到**空的**收件匣——訊息要有人推給他才存在。**寄信與發公告仍是手動開通**,濫發路徑沒有打開 |
| 「註冊 ≠ 授權」原則被稀釋 | 本申請不觸碰任何**業務系統**的授權;inbox 的讀取範圍恆為本人 |
| 日後被援引為先例 | 我方同意將核可範圍**寫死在「自我範圍資料的讀取」**;任何跨人可見的功能(寄信、公告、管理)一律回到 deny-by-default |
| 停用能力(§1.1 / D9=B) | 保留:`reader` 可由我方後台單獨停用,不依賴 IdP 帳號狀態 |

### 四、程序與前例

- upload-program 的「未登入開首頁可見說明性落地頁」是貴方**唯一經核准的偏離**(裁決見 `DOCS/回覆_upload-program_SSO接入申請_20260729.md`),程序可循:申請書 → 裁決文件 → 契約 §6 專屬條款登記。
- 🔴 **未獲核可前,我方照契約全 deny 實作**(首登零角色 → 403 待開通頁,頁上顯示本人 `sub`,§4.3 雞生蛋解法)。本申請不阻塞我方任何進度,只影響上線首日的體感。
- 若貴方認為此偏離不可開,請直接駁回;我方會在上線公告中寫明「首次使用需請管理員開通」,並把開通動線做進待開通頁。**我方要的是明確的答案,不是通融。**

## 陸、S2S 推送驗證規格 — 預告,本次不請求核發

契約 §6 記「首個 S2S 需求出現時補章節」;據我方所悉已有兩案排隊(**rf-workorder** 2026-08-14 送件、報告產生系統)。我方將是**第三案**,但**角色與前兩案相反**,故先揭露以便規格一次定完:

| | 前兩案 | cats-inbox |
|---|---|---|
| 角色 | **呼叫方**申請憑證去打別人的 API | **被呼叫方**——各系統要推通知進我方 |
| 需要規格回答的問題 | 我要什麼 scope | ① 我方如何**驗證**呼叫方(audience/scope 怎麼切)② 如何**辨識來源系統**(把 `source_app` 綁到呼叫方身分,而不是信任 body 裡的字串) |

🔴 我方紅線:**無驗證的推送端點不得部署到正式環境**,亦不以「先用共享 API key 頂著」上線。故 S2S 章節定稿前,推送 API(我方 T14)不對外開放;公告與收件匣(M3–M4)不依賴它,可先行上線。
正式申請將於我方 T13 送出;若貴方希望三案併案討論,我方可隨時配合提前提供需求書。
